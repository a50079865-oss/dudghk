## 0. 진단 — 사용자의 지적을 재료에서 확인한 것

사용자의 말: **"컷과 컷 간에 맥락이 없어, 개연성이."**
컨택트 시트와 QC 실측에서 원인 네 가지를 분리했다. 앞의 셋은 지시받은 것이고, **넷째는 컨택트 시트를 보다가 새로 나온 것**이다.

### (1) 41/42 컷이 정확히 5초 — 리듬이 내용과 무관하다
영상 컷은 Kling 클립이 5초라서 5초다. 장면이 5초여야 해서가 아니다.

### (3) 컷 지점이 동작이 아니라 소재 경계에 떨어진다
59개 하드컷 전부가 "클립이 끝나서" 끊긴다. 동작이 시작되기 전에 들어가고 완결된 뒤에 나오므로, 앞 컷의 동작을 뒤 컷이 **받지 않는다.** 없는 인과를 편집으로 만들 기회를 매 컷 버리고 있다.

### (4) ★ 새로 발견 — 같은 그림 두 장을 디졸브로 붙여 놓은 구간이 둘, 그리고 오염된 클립 하나

컨택트 시트를 셀 단위로 확대해 확인했다.

- **C022와 C023은 같은 그림이다.** 둘 다 *어두운 능선 실루엣 + 창백한 새벽 하늘*. 지시서상 C022는 "천막 사이로 새벽빛"이지만 실제 붙은 소재는 능선이다. 12초 + 8초 = **한 장의 그림이 20초**, 그 사이에 디졸브.
- **C038과 C039도 같은 그림이다.** 둘 다 *잔해 위의 흙 묻은 손*. 지시서상 C038은 "남겨진 잔해 와이드"지만 실제 소재는 손 클로즈업이다. 8초 + 18초 = **한 장의 그림이 26초**, 그 사이에 디졸브.
- 두 구간은 켄번스가 서로 **반대 방향**(풀아웃 → 푸시인 / 틸트업 → 틸트업)이라 디졸브 구간에서 이동량이 상쇄된다.
- **QC 리포트의 「12초 이상 정지」 2곳이 정확히 이 두 지점이다** — `2:32`(C021 끝~C022·C023), `4:18`(C037 끝~C038·C039). 기계가 이미 찾아낸 자리다. 길이가 문제가 아니라 **같은 그림을 디졸브로 이어 붙여 움직임을 0으로 만든 것**이 문제다.
- **C055가 오염 소재다.** 중간 프레임 상단 약 30%에 프롬프트 지시문이 그대로 구워져 있다 — `IDENTITY LOCK: render EXACTLY the same person(s)… / ANGLE BALANCE… / DEPTH & TEXTURE… / LIGHTING & ART…`. 아래쪽 그림(초가지붕 사이 골목에 몰린 군중, 탑다운)은 "길이 막힌다"에 맞지만, 글자가 5초 동안 화면에 뜬다.
  > 단서 한계: 컨택트 시트는 **중간 프레임 한 장**이다. 전 구간에 글자가 있는지는 클립을 직접 봐야 확정된다. 다만 Kling은 첫 프레임을 고정해 움직이므로 **전 구간에 있을 가능성이 높다**(추측).

## 1. 이 재편집안이 따르는 원칙 네 개

1. **길이는 내용이 정한다.** 질문은 짧게 끊고, 침묵은 길게 둔다. 결단 앞에는 멈춘다. 습격은 잘게 썬다.
2. **동작에서 자른다.** 동작이 시작된 뒤에 들어가고(IN), 완결되기 전에 나온다(OUT). 그러면 다음 컷이 그 동작을 **받는 것처럼** 읽힌다. 없는 연결을 편집으로 만드는 유일한 방법이다.
3. **인서트는 주인 옆에 붙인다.** 손은 그 손의 얼굴 바로 옆에 있어야 손이 된다. 한 컷만 떨어져도 자료화면이 된다.
4. **같은 그림은 한 컷이다.** 같은 그림을 둘로 나누고 디졸브로 잇는 것은 전환이 아니라 흐림이다.

## 5. 가장 큰 변화 5개

### ① C007 스틸을 둘로 나눠 침묵을 9.6초로 만든다 (S02)
`C006 → C007a(3.0s) → C009(3.4s) → C010(5.0s) → C007b(4.6s) → C011`
문제는 "침묵이 5초"가 아니라 **"질문도 5초, 침묵도 5초"**였다. 클립을 늘릴 수 없으니 **스틸을 빌려 침묵을 잇는다.** 질문 3.4초 : 침묵 9.6초 = 약 1:2.8. 그리고 C007b는 빈 시간이 아니라 **대답**이다 — 그녀는 말 대신 계속 일한다. C007a에서 주인이 이미 확정됐으므로 두 번째 등장은 정보가 아니라 의미가 된다.
*리스크:* 같은 스틸이 13초 간격으로 두 번 나온다. 켄번스를 충분히 벌려(102→105 / 106→110) 다른 프레이밍으로 보이게 해야 한다. 안 되면 C007b를 빼고 그 4.6초를 C012로 보내면 된다(합계는 유지된다).

### ② C020(잡은 손)을 C018과 C019 사이로 옮긴다 (S03)
`소년이 답한다 → 손이 손을 덮는다(12s) → 엘라라가 굳는다`
근거는 시트에서 확인한 사실이다 — **C020의 짚이 C018의 짚이고, C019는 돌벽 앞이다.** 인서트가 원인 자리로 오면서 세 가지가 동시에 해결된다: 손의 주인이 확정되고, 굳음에 원인이 생기고, 12초가 "들리지 않은 답의 무게"가 된다. **C019는 길이를 1초도 안 바꿨는데 무게가 달라진다** — 재편집이 할 수 있는 가장 싼 일이다.

### ③ C034(엄지)를 C032 뒤로 옮겨 「결단 직전 11초」를 만든다 (S05)
`C032 리븐이 계산한다(5.0s) → C034 엄지가 자루를 두 번 누른다(6s) → C033 요란이 올려다본다(4.2s) → C035 「…후퇴한다」`
현재는 요란 얼굴 뒤에 건틀릿 낀 손이 붙어 **요란의 손으로 읽힌다.** 리븐 옆으로 오면 주인이 확정되고, 동시에 **5초 클립으로는 못 만드는 11초짜리 정지**가 생긴다. 이 11초가 「…후퇴한다」를 명령이 아니라 **계산의 결과**로 만든다(대본이 `retreat`가 아니라 `withdraw`를 고른 이유와 같다). 그리고 C032(내려다본다) → C033(올려다본다)의 시선이 맞물린다.

### ④ 같은 그림 두 쌍을 각각 한 컷으로 합치고 디졸브를 진짜 경계로 옮긴다 (C022'·C039')
**QC가 이미 찾아낸 정지 2곳이 정확히 이 두 지점이다.** 원인은 길이가 아니라 **같은 그림을 둘로 나눠 반대 방향 켄번스를 디졸브로 겹친 것**이었다 — 이동량이 상쇄되어 화면이 실제로 멈춘다. 합치면 20초/26초가 18초/24초로 **짧아지면서 동시에 내내 움직인다.** 그리고 갈 곳을 잃은 디졸브 2개를 `C021→C022'`와 `C037→C039'`로 옮기면 원래 설계의 근거("시간이 흐른다" / "떠난 자에서 남은 자로")가 오히려 정확해진다. **삭제도 생성도 없이 정지 두 곳과 장면 전환 두 곳이 같이 고쳐진다.**

### ⑤ S08을 5초 균일에서 2.6~4.6초 불균일로 바꾼다
습격 14컷 중 **2.6초 2컷·3.0초 2컷을 연속으로 배치하고, 엘라라의 행동(C051 4.0)과 감정(C054 4.4)만 길게 남긴다.** 주변이 2.6초인데 그녀만 4.4초면 **길이의 대비만으로 시간이 멎는다.** 여기에 C055(오염 소재) 삭제가 겹쳐 S08이 77초 → 57.6초가 되는데, 이것은 손실이 아니라 **속도**다. 그리고 회수한 시간의 일부(3초)를 습격 **직전**의 C047(연기, 16초)로 보냈다 — 압력을 먼저 쌓고 짧게 터뜨리는 것이 오래 터뜨리는 것보다 세다.

### ※ 이 안이 감수하는 것 (솔직하게)
영상은 줄일 수만 있고 총 420초는 고정이므로, **줄인 42.6초는 전부 스틸로 갈 수밖에 없다.** 결과적으로 스틸 비중이 211초(50%) → 253.6초(60%)가 된다. 즉 이 재편집은 **「짧고 불규칙한 영상 컷 + 길게 버티는 정지 화면」**이라는 형태를 택한 것이다. 지시서가 시각 기준으로 삼은 Barry Lyndon의 타블로와는 맞지만, **사용자가 "너무 정지 화면 같다"고 느낄 여지는 분명히 있다.**
조절 레버는 단순하다 — **인출점 표에서 OUT 값을 키우면 그만큼 스틸에서 빼면 된다.** 가장 먼저 되돌릴 후보는 S08의 C049·C050·C052·C053(각 +1~2초)이고, 그 시간은 C047(16초)과 C043(16초)에서 빼면 된다.

## 6. 구현 메모 — `manifest.json`에 무엇을 추가하면 빌드가 이 안을 실행하는가

> **코드는 건드리지 않았다.** 아래는 필요한 스키마 변경과 데이터 형태만 적은 것이다.

### 6-1. `timeline` 항목에 추가할 필드

```jsonc
{
  "cut": "C003",
  "start": 22.0,
  "dur": 3.5,
  "tier": "B",
  "kind": "video",
  "source": "tCroSbcmZJ",
  "in": 0.8,          // ← 신규: 소스 클립 내부의 인점(초). 기본 0.0
  "out": 4.3          // ← 신규: 소스 클립 내부의 출점(초). 기본 = 클립 길이
}
```

- **불변식:** `out - in == dur` (허용 오차 1프레임). 빌드 시작 전에 검사해서 어긋나면 실패시키는 편이 안전하다.
- **범위:** `0.0 <= in < out <= 5.0`. 상한 5.0은 Kling 클립 길이다.
- `kind: "still"`에는 `in`/`out`을 넣지 않는다(무시).
- ffmpeg 기준으로는 `-ss {in} -to {out}` 또는 `trim=start={in}:end={out},setpts=PTS-STARTPTS`에 해당한다. **정확한 프레임 컷이 필요하므로 입력측 `-ss`(키프레임 스냅)가 아니라 출력측/필터 트림을 써야 한다.**

### 6-2. 순서 변경 — `start`를 신뢰하지 말고 배열 순서를 신뢰하게

현재 빌드는 `start`와 배열 순서가 항상 일치한다는 전제에 기대고 있을 가능성이 높다. 이 안은 **배열 순서 자체를 바꾼다**(C008·C020·C033·C034 이동). 두 가지 중 하나를 택하면 된다.

- **(권장)** `start`를 manifest에서 **지우고**, 빌드가 배열 순서대로 `dur`을 누적해 계산하게 한다. 길이를 한 번 고치면 뒤가 전부 자동으로 밀린다.
- 또는 `start`를 남기되 **빌드 시작 시 배열 순서대로 재계산해 덮어쓴다.** 어느 쪽이든 손으로 `start`를 유지보수하는 상태는 이 안에서는 유지될 수 없다.

### 6-3. 같은 스틸을 두 번 쓰기 (C007a / C007b)

`cut`을 고유 키로 쓰고 있다면 충돌한다. `source`는 같고 `cut`만 다르게 둔다.

```jsonc
{ "cut": "C007a", "dur": 3.0, "kind": "still", "source": "4RVOTgI9Aa",
  "ken_burns": { "mode": "in", "from": 1.02, "to": 1.05 } },
// … C009, C010 …
{ "cut": "C007b", "dur": 4.6, "kind": "still", "source": "4RVOTgI9Aa",
  "ken_burns": { "mode": "in", "from": 1.06, "to": 1.10 } }
```

다운로드 캐시가 `source`를 키로 잡혀 있으면 같은 파일을 두 번 받지 않으니 그대로 두면 된다. `cut`을 키로 잡혀 있으면 거기만 `source` 기준으로 바꾸면 된다.

### 6-4. 병합컷 (C022' / C039')

단순히 **두 항목을 하나로 합치고 켄번스를 한 번만 건다.** 표기는 원본 추적을 위해 `merged_from`을 남겨두면 나중에 되돌리기 쉽다.

```jsonc
{ "cut": "C022", "dur": 18.0, "kind": "still", "source": "1lN56wEr4r",
  "merged_from": ["C022", "C023"],
  "ken_burns": { "mode": "tilt_up", "from": 1.07, "to": 1.07, "shift_y": -0.07 } }
```
```jsonc
{ "cut": "C039", "dur": 24.0, "kind": "still", "source": "TdCWuqSVNR",
  "merged_from": ["C038", "C039"],
  "ken_burns": { "mode": "in", "from": 1.00, "to": 1.08 } }
```

> **소재 선택 주의:** C022/C023, C038/C039는 `source` ID가 서로 다르지만 그림이 거의 같다. 병합 시 **둘 중 화질이 좋은 쪽을 골라야 한다.** 이 문서는 컨택트 시트(리사이즈된 중간 프레임)만 봤으므로 어느 쪽이 나은지 판단하지 못했다 — 원본 두 장을 나란히 비교해서 정할 것.

### 6-5. 전환

`transition_after`는 이미 있는 필드다. **이동만 하면 된다.**

| 옮길 것 | 지금 붙은 컷 | 붙일 컷 |
|---|---|---|

이 안은 **C002부터 끝까지 모든 컷의 시작 시각이 바뀐다.** manifest의 다음 블록들이 전부 재계산 대상이다.

## 7. 이 문서가 확인한 것과 추측한 것

**컨택트 시트·QC 리포트에서 직접 확인한 것**
- C022와 C023이 같은 그림, C038과 C039가 같은 그림이라는 것
- QC의 정지 검출 2곳이 위 두 지점과 일치한다는 것
- C055 중간 프레임 상단에 프롬프트 지시문이 구워져 있다는 것
- C008의 광원·손이 C006·C007과 다르고 C015와 같은 계열이라는 것
- C020의 짚이 C018과 같고, C019는 돌벽 앞의 다른 공간이라는 것
- C030에 누워 있는 사람이 네 명이고, C033의 요란이 사슬갑옷 차림으로 잔해 위에 누워 올려다본다는 것 (= 그가 그 넷 중 하나로 읽힌다)
- C034가 건틀릿 낀 손이라는 것
- C036이 바닥 레벨에서 말 탄 자를 올려다보는 프레임이라는 것
- C004가 QC 정지 검출에 **안 걸렸다**는 것

**추측이며 확인이 필요한 것**
- C055의 글자가 클립 **전 구간**에 있는지 (중간 프레임 한 장만 봤다)
- C056의 약초 주머니가 엘라라의 것으로 읽히는지 (시트로는 소유를 확정할 수 없다)
- 각 클립 내부에서 동작이 정확히 몇 초에 시작/끝나는지 — **이 문서의 인출점은 컷의 성격과 중간 프레임에서 역산한 값이다.** 클립을 실제로 재생하면서 ±0.3초 정도는 조정될 것으로 본다. **조정 시 총합 420초를 유지하려면 같은 시퀀스 안의 스틸에서 반대 방향으로 빼고 더하면 된다**
- C008의 「왼손이 반 박자 늦게」가 1.2~3.8초 구간 안에 실제로 들어 있는지
- 병합할 두 쌍 중 어느 소재의 화질이 나은지

**확인하지 않은 것**
- 완성본 `part1.mp4` 자체(재생하지 않았다). 컨택트 시트와 QC 리포트의 수치만 근거로 삼았다
